# AWS SAA 問題集（Webアプリ）

AWS SAA の問題集を覚えるための、静的な Webアプリ。分野 → 章 → レッスンの順に、1文カードで覚えてから問題を解き、章末テスト・分野テスト・模擬試験で確かめる。学習の記録は、見ている端末のブラウザ（`localStorage`）に残る。

## 画面の言葉と、作り手側の用語

画面には、学ぶ人に分かる言葉だけを出す。データとプログラムの中は、作り手側の用語のままにしてある。

| 作り手側の用語（データ・プログラム） | 画面の言葉 |
|---|---|
| ブロック（`block` / `B001`〜） | 章 |
| ユニット（`unit` / `U001`〜） | レッスン |
| 済（`units[id] = true`） | 完了（✓） |
| ブロックの小テスト（`block.test`） | 章末テスト |
| 全問ランダム（`final_test` / `#/mock`） | 模擬試験（本番と同じ65問） |
| 模擬試験の合格の通算回数（`randomPassCount`） | 合格した回数 ◯回（段階6-22g で受験ライン `pass_times_for_exam_line` と「合格の目安」をやめた） |
| 組のカード（`question.card_ids`） | この問題を解くカード |
| 落とすカード（`links[].role` が `eliminate`） | ほかの選択肢が違う理由 |
| 違う点の組（`links[].contrast_pairs`） | 「問題文（違う点）｜カード」の表 |
| 苦手なカード（`state.cards`） | 苦手なカード |
| 条件のカード・事実のカード（`card_type`） | そのまま（画面では種類の名前を出さない） |
| 分野（`category`）、分野テスト（`categoryTests`。段階6-22で分野ごとに1つの30問にし、段階6-22c で27問以上の正解で合格にした） | そのまま |
| 章末テストの「合格まで」の問題（`testLeft['block:章ID']`。段階6-22c） | 合格まであと ◯問 |
| 用語集（`glossary.json`。段階6-20で作り、段階6-22で取り込んだ） | 用語集（答えたあとの用語のリンクと、`#/glossary` のページ） |
| 解説（`question.explanation` の `correct`・`wrong` の `reason`。段階6-15d・6-15e で作った） | 「C が正解の理由」の「✓ C を選べる」の下の文・「✕ A は不正解」の下の文 |
| 予定（`plan`）・今日の一覧（`today`） | スケジュール・今日やること |
| 今日の一覧の行を終えた（`today.items[].done`） | 済（✓ は使わない） |
| 復習の山（`reviewPool`。予定日が来た復習の残りの問題をまとめたもの） | 復習（今日やることの「復習　残り◯問」の1行。段階6-21。スケジュールが無ければホームの「復習　残り◯問」の1行。段階6-22h） |
| 復習の残り（`reviewLeft`） | 残り ◯問 |
| 1日の目標（`dailyTarget`） | 1日に解く問題の目安（スケジュールのページだけに出す） |
| 進捗・進み具合（`state`） | 学習の記録（「進み具合」という言葉は画面に出さない） |
| 補足（`back_note`） | 答えの下の小さく薄い文（見出しは付けない） |
| ② の間違いの選択肢（`check_choices`） | そのまま選択肢として出す |

レッスンの4つのタブ（段階6-9で、進む段階からタブに変えた。「段階」という言葉は画面に出さない）：

| 中身 | 画面の言葉 |
|---|---|
| カードの表と裏を見て覚える | ① 覚える |
| カードの表を見て、似た答えの中から正しい答えを選ぶ（段階6-13で選択式にした） | ② 確かめる |
| ヒント付きの問題 | ③ 演習（ヒントあり） |
| ヒントなしの問題 | ④ 演習（ヒントなし） |

## 作りの決まり

- ビルド（変換の工程）を使わない。置いたファイルが、そのまま動く
- 外部の部品（ライブラリ・CDN・外部のフォント・解析タグ）を使わない。すべてこのフォルダの中で完結する
- JavaScript は ES モジュール。画面の切り替えは URL の `#` 以降で行う（ブラウザの「戻る」が効く）
- 問題・カード・並び順は `data/` の3ファイルから、設定値は `settings.json` から読む。データの中身をプログラムに書き込まない
- `alert`・`confirm`・`prompt` は使わない。確認は画面の中に出す
- 途中でやめたら、そのレッスン・その演習は最初から（途中の状態は保存しない）。復習の山と章末テスト・分野テストは、解きかけの画面は保存しないが、1問ごとの答え（残り・「合格まで」からの出し入れ、苦手な問題の出入り）は保存する（段階6-21・6-22c）。そのため、復習・章末テスト・分野テストでは、途中で離れるときの確認のウィンドウを出さない（段階6-22）
- **使い方に書いてあることは、ほかの画面に出さない**（操作に欠かせない表示だけ残す）
- 問題集の元の解説は使わない・出さない。出す理由の文は、このアプリのために書いた解説（`explanation`。段階6-15d・6-15e）だけ
- **`app/` を変えたら、最後に必ず `python3 tools/stamp_version.py` を動かす**（プログラムのファイルの呼び名に版の番号を付け直す。下の「版の番号」。段階6-22b）

## 手元で動かす方法

このフォルダ（`app/`）で、次を実行する。

```
python -m http.server
```

ブラウザで `http://localhost:8000/` を開く。
`index.html` をファイルとして直接開くと、`data/` を読めないため動かない。

## 版の番号（段階6-22b）

**`app/` のファイルを変えたら、最後に必ず `app/` で次を動かす。** 段階ごとの指示書に書いていなくても行う。

```
python3 tools/stamp_version.py
```

- なぜ付けるか：ブラウザは、前に読んだプログラムのファイルを覚えていて、ふつうの更新（F5）でも使い回すことがある
  （`python -m http.server` は「覚えてよいか」を伝えない。GitHub Pages でも、公開から約10分は古いファイルが使われることがある）。
  古いファイルと新しいファイルが混ざると、新しいファイルにしか無い部品が見つからずに「読み込み中…」のまま止まる。
  呼び名に `?v=番号` を付けておけば、番号が変わったときにブラウザは別のファイルとして必ず新しく読む
- 番号：`index.html`、`js/` の `.js`、`css/` の `.css`、`settings.json`、`data/` の `.json` の中身から計算する（SHA-256 の先頭10文字）。
  付けてある番号の部分を取り除いた中身を名前の順に使うので、中身が同じなら何度動かしても、どのPCでも同じ番号になる
- 付く場所：
  - `index.html` の `js/main.js?v=番号` と `css/style.css?v=番号`
  - `js/` の `.js` の中の、`./`・`../` で始まり `.js` で終わる呼び名（`import … from '…?v=番号'` など）
  - `js/main.js` の `APP_VERSION`（いま動いているプログラムの番号）
  - `version.json`（`{ "version": "番号" }`。いま置いてある版の番号）
- `data/` の JSON と `settings.json` の読み込みには付けない（`cache: 'no-cache'` で毎回確かめて読む）
- 開いたときの確かめ（`js/main.js` の `reloadIfOld`）：データを読む前に `version.json` を `cache: 'no-store'` で読む。
  番号が `APP_VERSION` と違い（＝開いたページ `index.html` が古いまま）、いまの行き先の `?v=` もその番号でなければ、
  `?v=番号` を付けて1回だけ読み直す（行き先の `#/...` はそのまま）。`version.json` が読めない・番号が同じ・
  すでに `?v=` がその番号のときは、何もせずに続ける。学習の記録には一切さわらない
- 道具は、何も変わっていなければファイルを書き換えない（更新日時も変えない）。
  `python3 tools/stamp_version.py --check` は書き換えずに確かめ、違うファイルと場所を表示して0以外で終わる
- 付け忘れ・付け違いは `tools/check_data.py` の項目30で見つかる
- 手で `?v=…` や `APP_VERSION` を書き換えない。ファイル名そのもの（`plan.js` など）は変えない

## 画面の上のメニュー

- 上の帯の**右上**のボタン（線で描いた三本線）を押すと開く。中身は、ホーム・分野（7つ）・模擬試験・苦手な問題（n問）・苦手なカード（n枚）・用語集・スケジュール・記録を移す（段階6-22j）・使い方・**学習の記録を消す**
- 「学習の記録を消す」はホームには置かない。押すと、確認のウィンドウ「学習の記録をすべて消して、最初の状態に戻します。消しますか？」を出す
- ホーム以外の画面には、ページの名前の上に戻るリンク（「‹ ホーム」「‹ ストレージ」など。1つ上の画面へ。レッスン・テスト → 分野、それ以外 → ホーム。段階6-22）
- レッスンの ③・④・苦手な問題・模擬試験の**途中**で（復習・章末テスト・分野テストは除く。段階6-22）、メニューから別の画面へ移るとき、またはブラウザの「戻る」で離れるときは、確認のウィンドウ「いま解いている問題は、最初からになります。移動しますか？」を出す（「移動する」「続ける」）

## 印（段階6-14）

- ホームの「今日やること」：まだの行を上、終えた行を下（それぞれの中は一覧の順）。まだの行は白抜きの丸、終えた行は緑の塗りつぶしの丸と白いチェック・取り消し線・薄い色（「済」の文字は出さない）。行の頭に小さく「復習」「レッスン」「章末テスト」「分野テスト」「模擬試験」。上の「2 / 4」と緑の細い棒
- 今日やることを全部終えたとき（段階6-22m）：見出しを「今日の分は完了！」（緑の文字。「◯ / ◯」と進みの帯は今のまま）にし、そのすぐ下に次にやることの行、区切りの線、終えた行（一覧の順）を並べる。次にやることの行は、スケジュールが無いときのホームの 2・3 と同じ（始めたまま合格していない章末テスト「あと◯問」をすべて〈今日の一覧で済にした章末テストでも、合格していなければ出す〉と、`homeNext` の次にやること1行）。復習・模擬試験の行はここでは出さない。どれも無ければ、見出しのすぐ下に終えた行。別の行としての「今日の分は完了！」と「次のレッスンへ」は出さない（段階6-22m でやめた）
- 分野の画面：レッスンの行の左に丸（まだ＝白抜き、完了＝緑の塗りつぶしの丸と白いチェック）。章の全レッスンが完了したら、章の見出しの「n / n」を緑の文字に
- テストの行（章末テスト・分野テスト）：オレンジの地と文字に、線で描いた鉛筆の絵

## レッスンの4つのタブ

- 上に4つのタブを置く。**いつでも自由に移れる**
- ③・④ で**1問以上答えたあと**に別のタブへ移るときだけ、確認のウィンドウを出す（移ると、その演習は最初からになる）
- ①・②・③・④は、細い棒（解いた分を青く伸ばす）と右端に小さく「1 / 5」（段階6-21。テスト・復習・苦手な問題・苦手なカードの練習も同じ。① は段階6-22g から。① の棒は**いま見ているカードまで**を埋め、最後のカードでいっぱい。「前へ」で戻ると棒も戻る）。タブの下に説明の文は出さない
- ① 覚える：表と答えを両方見せる。**補足（`back_note`）は、答えの下に小さく薄く**出す（答えは大きく太く）

## 記録を移す（段階6-22j）

学習の記録は、それぞれの端末のブラウザ（`localStorage` の `aws-saa-study`）にだけ残る。別の端末で続けるときは、サーバーを使わず、記録を JSON ファイルに書き出し、別の端末で読み込む（`js/screens/transfer.js`。読み込みは置き換えだけで、足し合わせはしない）。

- ページ（`#/transfer`。メニューの「使い方」の上の「記録を移す」）：見出し「記録を移す」（戻るリンクは「ホーム」）、説明「別の端末で続きをするときは、この端末で記録を書き出し、そのファイルを別の端末で読み込みます。」、番号つきの手順3つ、目立つ「記録を書き出す」・控えめな「記録を読み込む」、注意「読み込むと、その端末の記録は、読み込んだ記録に置き換わります。」。保存が使えない環境では、ボタンの代わりに「このブラウザでは記録を保存できないため、記録を移せません。」
- **書き出す**：`Blob` と `a[download]` でファイルを保存させる。ファイル名は `aws-saa-study-記録-YYYYMMDD-HHMM.json`（書き出した日時。端末の時刻）。書き出しで記録は変えない。「記録を書き出しました。」と知らせる
- **ファイルの形**（UTF-8、JSON）：

```json
{
  "app": "aws-saa-study",
  "kind": "study-record",
  "exported_at": "2026-10-23T17:14:00+09:00",
  "version": 8,
  "state": { "...": "保存している記録そのまま" }
}
```

  `exported_at` は端末の時刻（時差つき）。`version` は保存の形の版（`js/logic/migrate.js` の `VERSION`）。`state` は保存している記録そのまま（`storage.js` の `exportState`。画面用に、いまのデータに無いIDを除いたもの〈`getState`〉ではない）
- **読み込む**：「記録を読み込む」で、見えないファイルの入力（`accept=".json,application/json"`）を開く。入力の値は毎回空にする（同じファイルを続けて選んでも読み込める）。読んだファイルを次の順に確かめ、だめなら読み込まずに知らせる（確認のウィンドウ。ボタンは「閉じる」だけ）
  1. JSON として読める・`app` が `aws-saa-study`・`kind` が `study-record`・`state` が物の形 → だめなら「このファイルは読み込めません。このアプリで書き出したファイルを選んでください。」
  2. `version`（と `state.version`）が今の版（8）より大きくない → だめなら「このファイルは、新しい版のアプリで書き出されています。アプリを開き直してから、もう一度読み込んでください。」
  3. `version` と `state.version` が1以上の整数（版の分からない記録は、移し替えで初めの状態になってしまうため読み込まない）→ だめなら 1. と同じ文
- 通ったら確認「この端末の記録を、10月23日 17:14 に書き出した記録に置き換えます。よろしいですか？」（日時は `exported_at` を、読み込む端末の時刻で出す。読めなければ「書き出した記録に置き換えます。よろしいですか？」）、「置き換える」「戻る」。「置き換える」で、`state` を開いたときと同じ移し替え（`migrateState`。版7以前の記録は今の形に移す）に通してから保存している記録を置き換え（`storage.js` の `replaceState`。覚えている記録・画面用の記録も作り直す）、今日の一覧を作り直し（`refreshToday(true)`）、ホームへ移って「記録を読み込みました。」。「戻る」なら何も変えない

## 見た目の決まり（段階6-13・見本B）

- 問題の面（③・④・テスト・苦手な問題の問題文、② と苦手なカードの練習のカードの問い、テストの結果の見直しの問題文）は、① のカードの「問い」と同じ地 `#F5F7FA`（`--q-face`）。選択肢は白のまま（段階6-17）
- 地 `#F2F4F7`、面 `#FFFFFF`、文字 `#121826`、薄い文字 `#5B6576`、アクセント `#2847C9`、テスト `#A2480F`／`#FDEBDD`、正解 `#1E7A4C`／`#E3F4EA`、問題文の色 `#FFE58F`。不正解は `#8F1D14`／`#FBE5E1`（正解の色より暗く、明るさでも区別できる）
- 白い面は角の丸み16〜20px。枠線は使わず、すき間で区切る（選んだ・正解・不正解の選択肢だけは2pxの線で示す）
- 文字は端末にあるもの（`"BIZ UDPGothic", "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", "Noto Sans CJK JP", "Yu Gothic UI", …`）。読み込まない

- ボタン・行の高さは最低44px
- 端末が「動きを減らす」設定のときは、カードの裏返る動き・間違えたときの揺れ・正解の印の動き・「クリア！」の弾む動きを使わず、色と文字だけで示す
